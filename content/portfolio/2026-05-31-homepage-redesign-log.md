홈페이지가 "$200짜리"처럼 보였다. 깔끔하긴 한데 어디서 본 듯하고, 나만의 관점이 없었다. 그래서 기준을 하나 들고 와서 점검부터 하기로 했다. Metics Media가 정리한 *The $10K Checklist* — "1만 달러짜리 웹사이트와 200달러짜리를 가르는 여덟 가지"다.

## 출발점: 여덟 가지로 점검

체크리스트는 이렇게 묻는다. ①템플릿이 아닌 관점이 있는가 ②일하는 타이포인가(Inter·Roboto 금지) ③색은 3~5색으로 절제됐는가 ④여백·대비로 위계가 숨 쉬는가 ⑤이미지에 의도가 있는가 ⑥모션이 속삭이는가 ⑦모바일이 축소가 아니라 설계됐는가 ⑧보이지 않는 고급(빠른 로드·접근성·시맨틱·메타)이 있는가.

소스를 펼쳐 놓고 한 항목씩 매겼더니 평균 5.75/10. 강점은 세리프 제목과 시맨틱 구조, 약점은 색(카테고리 5색이 무지개처럼 튄다), 이미지(빈 자리에 그라데이션만), 그리고 보이지 않는 고급(키보드 포커스도, 공유 메타도 부실)이었다.

## 디자인 시스템부터 뽑기

바로 CSS를 만지고 싶은 충동을 눌렀다. 먼저 방향을 글로 못 박아야 매번 흔들리지 않는다. `ui-ux-pro-max`로 제품 유형·스타일·타이포·색을 한 번에 돌려 **Editorial / Swiss Modernism**(그리드·수학적 여백·절제) 방향을 잡고, 타이포는 잡지형 페어링(세리프 디스플레이 + 깔끔한 산세 본문), 색은 "잉크 + 종이 + 단일 강조"로 정리했다. 이걸 `DESIGN-SYSTEM.md`로 박아 두고 시작했다.

그다음 `frontend-design` 기준으로 전역 CSS를 다시 썼다. 클래스 이름은 그대로 두고(템플릿이 안 깨지게) 토큰·타이포·여백·모션만 갈아끼웠다.

## 세 번 방향을 바꿨다

여기서부터가 진짜 고민이었다. 처음엔 따뜻한 종이 + 에버그린(v2)으로 갔다. 그런데 미리보기를 보니 "원래랑 큰 차이가 없네" 싶었다. 그래서 **어둡고 전문적인** 콜드 스틸 다크(v3)로 틀었다가, 다시 "모던하고 심플한 개인 블로그"가 더 맞겠다 싶어 **쿨 화이트 + 코발트(v4)**로 안착했다.

세 번 갈아엎으면서 배운 건, **색은 토큰으로 묶어 두면 통째로 갈아끼우는 비용이 거의 0**이라는 것. `--bg`, `--ink`, `--accent` 몇 개만 바꾸면 전 페이지가 따라온다. 그리고 색을 고를 때 코발트 원안(#2f6df6)은 흰 배경 위 본문 링크 대비가 4.4:1로 AA(4.5)를 아슬아슬하게 못 넘겨서, 한 단계 깊은 #2563eb로 잡았다. 인상은 그대로면서 대비는 통과한다.

## 약점 두 개를 집중 보강

점검에서 가장 낮았던 ⑤이미지와 ⑧보이지 않는 고급을 따로 끌어올렸다.

**⑤ 이미지** — 사진이 없는 글도 "의도된" 모양이 되도록, 빈 자리를 그라데이션 대신 *편집형 마크*로 바꿨다. 톤 패널 + 도트 텍스처 + 세리프 모노그램 + 카테고리 워드마크 + 미세 인셋 프레임. 사진 유무와 상관없이 카드가 커미션된 것처럼 보인다.

**⑧ 보이지 않는 고급** — canonical, Open Graph, Twitter 카드, 글마다 `BlogPosting` JSON-LD, 내비게이션 `aria-current`, 이미지 `decoding=async`를 채웠다. 그리고 SNS에 공유될 때 모든 글이 같은 카드로 나가도록 **기본 대표 공유 이미지**를 만들었다. 브라우저 캡처 도구가 없어서, 사이트와 같은 토큰으로 SVG를 짠 뒤 `sharp`로 PNG(1200×630)로 구웠다.

타이포와 여백도 손봤다. 한글 본문은 Pretendard로 바꾸고(`word-break: keep-all`로 단어가 어색하게 끊기지 않게), 줄간격을 올리고(본문 1.75, 글 1.85), 제목은 키우기보다 살짝 줄이고 **여백으로 위계**를 만들었다. 섹션 간격을 64→92px로, 본문 패딩을 넉넉하게.

## 배포

`main`에 푸시하면 GitHub Actions가 빌드해서 GitHub Pages로 올린다. 푸시하려는데 원격에 새 글(자동 수집된 것들)이 먼저 들어와 있어서 rebase로 얹은 뒤 다시 밀었다. Actions는 build·upload·deploy 전부 통과(deploy 11초), 라이브에서 코발트 토큰·Pretendard·canonical·OG 이미지(200 OK)까지 확인했다.

## 남은 것 / 배운 것

- 색을 토큰으로 묶어 두면 방향 전환이 싸다. 세 번 갈아엎고도 본문 템플릿은 한 줄도 안 건드렸다.
- "점검 → 시스템 → 구현" 순서를 지키면 취향 싸움이 줄어든다. 기준이 먼저 있으니까.
- 접근성·메타 같은 보이지 않는 항목은 점수로 만들어 두지 않으면 계속 미뤄진다.
- 다음 후보: GitHub Actions의 Node 20 deprecation 경고 정리, 글별 맞춤 OG 카드 자동 생성.

도구로는 점검에 체크리스트, 시스템화에 `ui-ux-pro-max`, 구현에 `frontend-design`, 이미지 생성에 `sharp`를 썼다. 하루치 의사결정을 이렇게 남겨 둔다.
